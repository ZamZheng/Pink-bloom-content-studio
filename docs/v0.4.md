# V0.4 通用视觉系统与外部背景确认

这是渲染能力升级，正文与布局配置仍为 draft；2026-11-23固定品牌规范除外（见docs/brand-identity.v1.md）。没有制作、替换或提交第003期成品，没有连接 Notion/API、申请 Token、开发后台或发布服务。

## 两张参考图的差异

早期作品的优势在于：主标题与正文的衬线气质连贯，小标题有更明显的深绿与字重，正文安静而清晰，豆沙粉斜体数字形成阅读节奏，底部有小型花瓣感标识。

第三期测试稿保留了整体暖白调性，但引导语和正文转为普通无衬线，编号也继承正文字体，小标题相对变弱；图标按旧库顺序选择，和肩臂、指导、穿衣语义关联不足；品牌仅剩文字。背景中的静物语义还缺少独立的人为确认。这些问题不能靠固定复制旧图构图解决。

V0.4保留可重复的字体角色、图标规范和品牌组件，同时把内容区、背景、安全区和间距继续作为配置。工程样张使用自行绘制的无字中性测试背景，不复制任何参考海报的摄影构图。

## 升级前后

| 能力 | 旧版 | V0.4 |
| --- | --- | --- |
| 字体 | 部分角色共用字体/字号变量，编号继承正文 | 八个独立角色；真实字重和斜体；禁止浏览器合成 |
| 编号 | 跟随正文 | 独立 Libre Baskerville 400 italic，豆沙粉 |
| 图标 | 内容中可指定旧ID，缺乏统一语义约定 | 显式ID或语义别名；未知语义有可解释回退；不读取序号选图 |
| 品牌 | 一行中文及局部颜色 | 稳定SVG符号＋文字＋粉红强调；符号确认状态留痕 |
| 3/4条 | 自然流已存在 | 明确校验3—4条，提醒随实际内容上移，无空白第四槽 |
| 背景 | 仓库内图片，缺少独立审核关卡 | 本地临时PNG、质量/几何检查、图像及安全区摘要绑定人工确认 |
| 导出 | 排版检查后导出 | 排版检查＋背景人工确认后才能正式合成；诊断不覆盖已有PNG |
| 历史版本 | 第002期v2已锁 | 原入口、原锁及所有锁定字节完全保留 |

## 安装与入口

```bash
npm ci
npm ci --prefix v04
npm run setup:browser

# V0.4 新入口（不替换原render.mjs）
node scripts/render-v04.mjs --background-preview --config /tmp/run/config.json --output /tmp/run/background.html
node scripts/render-v04.mjs --preview --input /tmp/run/content.json --config /tmp/run/config.json --output /tmp/run/preview.html
node scripts/render-v04.mjs --input /tmp/run/content.json --config /tmp/run/config.json --output /tmp/run/card.png
```

受限云环境可将npm cache和浏览器目录设在可写位置，例如 `--cache /tmp/pink-bloom-npm-cache`、`PLAYWRIGHT_BROWSERS_PATH=/tmp/pink-bloom-playwright`。这些是环境设置，不需要修改源代码。

根依赖包保持旧版图形引擎的0.3.0依赖封套；V0.4版本及新增字体独立登记在 `v04/package.json` 和 `v04/package-lock.json`，避免更改已锁定的根 `package-lock.json`。新入口复用根依赖中的Playwright和Noto，新增Libre字体由独立lock安装。运行时禁止外部HTTP资源，全部字体与图像本地加载。

## Typography Tokens

通用配置：`config/design/pink-bloom.v0.4.json`。

| 角色 | 默认字体 | 大小/字重 | 行高/颜色 |
| --- | --- | --- | --- |
| heroTitle | Noto Serif SC | 64 / 600 | 1.5 / #51483f；强调#52613f |
| introduction | Noto Serif SC | 25 / 400 | 1.6 / #847a70 |
| pointHeading | Noto Serif SC | 32 / 700 | 1.5 / #52613f |
| pointBody | Noto Serif SC | 24 / 400 | 1.5 / #51483f |
| pointNumber | Libre Baskerville | 46 / 400 italic | 1.5 / #b7827b |
| reminderHeading | Noto Serif SC | 29 / 600 | 1.5 / #52613f |
| reminderBody | Noto Serif SC | 23 / 400 | 1.5 / #51483f |
| brandSignature | Noto Serif SC（固定品牌规范控制） | 22 / 400 | 1.5 / #123f54；社区全称#9b718b |

每个角色独立配置 `family / size / weight / lineHeight / color / tracking / style`，可选 `emphasis: {color, weight, style}`。提醒拆成两个角色以避免标题和正文互相影响。字距单位px，字号单位CSS px。修改设计参数应新增版本化draft配置，不必修改HTML/CSS。

Fontsource Noto Serif SC / Noto Sans SC 均锁定5.3.1；Noto Serif SC实际提供200—900的常规字形，没有斜体。编号新增 `@fontsource/libre-baskerville@5.3.0`，实际提供400/500/600/700的正常与斜体字形。许可均为SIL OFL 1.1，随npm包的LICENSE及metadata保存；来源是Google Fonts/Fontsource，不含商业字体。V0.4按包metadata和对应CSS校验每个配置字重/字形，并实际等待浏览器加载；`font-synthesis:none`禁止伪粗体/伪斜体，CDP报告每个角色实际使用的自定义字体。Latin字体仅用于编号，不能用于中文角色。

字段强调使用本期配置中的 `textEmphasis`，例如 `{"heroTitle":["阅读更从容"]}`；知识点可用 `emphasis:{heading:["关键词"],body:["关键词"]}`。强调词必须在对应原文中存在，不能改变文案。编号始终由实际知识点顺序生成01—03或01—04。

## 语义图标

统一注册表：`config/icons/library.v04.json`；通用SVG：`assets/icons/v04/`。全部使用48×48 viewBox、1.6描边、currentColor、无外部资源，颜色和圆底由设计配置控制。

```json
{
  "heading": "本条小标题",
  "body": "本条完整正文",
  "iconSemantic": "专业指导"
}
```

或显式指定 `"iconId":"professional-guidance"`。旧字段 `icon` 可作为显式ID别名，但须在新库中存在。制作人员先阅读小标题/正文、提炼语义，再选ID；Node渲染器不调用AI，也不能自动保证一个合法ID与任意正文语义相符。

| ID | 用途/别名举例 |
| --- | --- |
| shoulder-arm | 肩臂活动、肩膀紧绷 |
| professional-guidance | 专业指导、医护评估 |
| gentle-mobility | 轻柔活动、动作范围 |
| daily-dressing | 穿衣、日常动作 |
| calendar | 恢复时间 |
| water-drop | 温柔清洁 |
| skin-care | 保湿护理 |
| sun-protection | 阳光防护 |
| general-info | 无精确图标时的通用信息符号 |

显式错误ID直接失败；缺少ID及语义直接失败。未知语义使用general-info，并在报告说明回退原因。SVG文件缺失、损坏或包含脚本/外部资源均报错，不随机替代。新增图标时增加统一SVG及注册条目即可，无需改变HTML/CSS。报告记录每个知识点的实际ID、语义、选择来源和资源摘要。

## 品牌组件

新生产默认加载锁定的 `config/brand/identity.v1.json`：栏目叶片＋康复小纸条＋NO.NNN、下方PINK BLOOM、完整双瓣小标＋向光而行 粉红伙伴社区。颜色、文字、真实字体与强调范围独立于本期正文主题，详见 [固定品牌规范](brand-identity.v1.md)。

原 `brand-signature.v1.json` / `petal-candidate.v1.svg` 作为历史候选保留；新版入口不再接受切回候选或自定义Logo。新规范的两枚SVG是依据用户指定的验证图建立的稳定实现，不冒称取得原始官方矢量。位置/安全区仍按本期背景配置；组件内部文字、颜色、符号比例和间距保持固定。后续品牌调整必须新建版本并登记摘要。

## 三条与四条布局

内容JSON必须有3或4个 `{heading,body,iconId或iconSemantic}` 对象。所有文字以textContent注入并逐项核对，不截断、重排、删减或自动缩字。列表、知识点标题/正文和提醒都自然流动；三条时不会创建第四节点，提醒跟随内容上移。

每期parameters可调 `titleWidth/titleAlign/introGap/pointsGap/pointGap/rowPadding/columnGap/iconColumn/numberColumn/iconDiscSize/headingGap/rowAlign/ruleWidth/reminderGap/reminderRadius/reminderPadding/brandAlign/brandGap/brandSymbolSize`。默认值在新配置加载器中统一管理，输入未知参数会报错；`ruleWidth:0`可关闭分隔线。品牌内部的brandGap与brandSymbolSize由锁定规范覆盖，旧参数不再改变组件内部比例；brandSignature角色及brandPink/brandSymbol也不控制固定品牌组件。安全区不足时保留预览/报告并报错，字号保持原值。布局预设使用带id/version/status的独立文件，每期parameters覆盖预设参数；背景同样记录独立id/version及人工流程状态。

## 背景确认关卡

工作流：**文案确认 → 制作无字背景 → 独立背景预览 → 用户确认 → 合成排版 → 最终视觉验收**。

本期配置使用schemaVersion=4，并引用通用design/brand配置，背景与几何标注可直接驻留本次临时目录：

```json
{
  "schemaVersion":4,
  "id":"runtime-card",
  "version":"1",
  "status":"draft",
  "design":"config/design/pink-bloom.v0.4.json",
  "brand":"config/brand/identity.v1.json",
  "layout":"config/layouts/editorial.v0.4.json",
  "parameters":{"pointGap":4},
  "background":{
    "id":"runtime-background",
    "version":"1",
    "file":"/tmp/run/background.png",
    "assetRoot":"/tmp/run",
    "status":"pending",
    "geometry":{
      "canvas":{"width":1080,"height":1350},
      "imageSha256":"填写实际PNG摘要",
      "safeAreas":{
        "masthead":{"x":72,"y":30,"width":780,"height":82},
        "content":{"x":72,"y":135,"width":936,"height":1090},
        "brand":{"x":510,"y":1245,"width":500,"height":65}
      },
      "avoidAreas":[]
    }
  }
}
```

这是结构示例，摘要必须换成真实值、安全区必须根据本期画面重新标注，不能复制坐标就声称已确认。`file`相对配置目录或绝对路径均可，限定在明确的assetRoot（默认配置所在目录）或仓库背景目录，符号链接逃逸和远程URL被拒绝。导出不能覆盖输入背景或已锁定归档素材。

背景状态：`pending`待确认、`needs_changes`需修改、`confirmed`已确认。前两种状态允许 `--background-preview`（无字图＋安全区辅助线）和`--preview`（技术排版诊断），但禁止正式PNG合成。技术预览报告将 `ok`（几何/质量）与 `exportAllowed`（同时满足确认）分开，不能把排版通过当作背景已获人工确认。

用户确认背景和安全区之后，由外部工作流填写：

```json
{
  "by":"实际人工审核者",
  "at":"实际确认时间的ISO字符串",
  "textFree":true,
  "imageSha256":"确认图片的SHA-256",
  "geometrySha256":"确认安全区标注的摘要"
}
```

该对象放入 `background.confirmation`，背景status才能改为confirmed。`geometrySha256`通过 `scripts/config-v04.mjs`导出的 `geometryHash(geometry)`计算（递归排序键后JSON SHA-256），`geometry.imageSha256`也绑定图片。可从背景预览report读取这两个摘要，但程序不提供“自动批准”命令，也不能根据清晰度推断人工确认。

换图片即使尺寸相同也会导致旧几何imageSha256失效；重新标注后，旧确认中的geometrySha256同样失效。修改任何安全区必须重新核对并传入新的人工确认记录。程序不宣称能辨别是否有人复制了旧坐标，摘要只阻止静默沿用旧确认；物体含义、场景逻辑、光影合理性、无字性及最终审美均由人判断。

质量检查：PNG签名/解码、真实尺寸、至少2160×2700、严格4:5、1080×1350标注坐标、安全区几何、文本溢出/相交/裁切/装饰避让。比例不符不自动裁切，避免更改标注含义。所有正式PNG为2160×2700，检查失败或背景未确认时不覆盖已有PNG。

旧版入口用于复现历史确认版本，不具备V0.4背景关卡；新生产必须明确调用render-v04.mjs。不能通过改用旧入口把未确认的V0.4配置导出，旧入口不识别其schema；历史兼容不等于给新流程绕过审核。

## 版本与数据边界

旧 `scripts/render.mjs/config.mjs/preflight.mjs`、已锁模板/配置/素材、根lock与`config/versions.lock.json`原样保留，新增入口也会校验全部历史锁。新能力使用独立文件，不删除或重写锁信息。

Notion负责每期业务内容、人工确认、背景和成品；渲染程序本身不连接Notion（SOP规则由外部执行者同步）。GitHub只保存程序、设计配置、图标、通用测试和文档；Codex运行目录保留临时JSON/预览/样张。第003期文件未纳入本开发分支。
